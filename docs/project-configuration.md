# Проектная конфигурация и языковые политики

`scan`, `extract` и `check` требуют канонический `.language-review.yaml` в корне
каждого целевого репозитория. Файл задаёт политику этого репозитория и не выдаёт
сетевых полномочий. `.coderabbit.yaml` относится к ревью кода другим инструментом;
его поля и инструкции здесь не используются.

```powershell
language-review init .\repo
language-review config validate .\repo
language-review config show .\repo\docs\guide.md --format json
language-review check .\repo --view review --format json
```

`init` — явная запись минимального локального шаблона. Существующий файл, включая
ссылку, никогда не перезаписывается. Проверка YAML не запускает движки. Обычные
команды анализа не создают конфигурацию. Канонический файл и прочитанные файлы промптов не входят в обход
исходников: они принадлежат политике, а не проверяемому тексту.
Запись отчёта поверх YAML или прочитанного файла промпта запрещена.

## Корень и пути

Абсолютный путь не зависит от `cwd`; относительный отсчитывается от `cwd`.
После разрешения цели ближайший родитель с `.git` (каталогом либо файлом worktree)
является единственным корнем. Конфиг из родительского репозитория не наследуется.
Запуск из подкаталога и выбор одного файла используют тот же корень. Вложенные
Git-репозитории при обходе пропускаются как `nested_repository`; передайте их
отдельными целями с собственными конфигурациями.

Вне Git корень — сам указанный каталог либо родитель автономного файла. Подъёма
к конфигам родительских каталогов нет: для не-Git дерева указывайте его корень.
Обнаруженный корень без YAML даёт ошибку конфигурации, код 2. `.yml`, файлы другой
регистрозависимой формы имени и вложенные конфиги не служат альтернативами.
`--help`, `--version`, `show-review`, `verify-review`, OAuth и команды памяти не
требуют политики целевых исходников. `doctor` диагностирует пользовательскую среду;
проверка проектной политики принадлежит `config validate`/`config show`.

## Строгий контракт версии 1

```yaml
schema_version: 1
default_profile: everyday
profiles:
  everyday:
    engines: [languagetool, vale, llm]
    categories: [spelling, grammar, terminology]
    terms: {апдейт: обновление}
    analysis:
      mode: normal
    llm:
      provider: llama_cpp
  docs:
    engines: [llm]
    analysis:
      mode: deep
      strategies: [grammar, spelling, punctuation, technical, meaning, english]
      verify: true
      max_requests: 100
      max_text_chars: 200000
      concurrency: 2
    llm:
      provider: chatgpt
      model: gpt-6.1-sol
      reasoning_effort: high
    prompts:
      strategies:
        technical: {text: 'Проверяй точность терминов пользовательского руководства.'}
path_rules:
  - {path: 'docs/**', profile: docs}
prompts:
  primary: {text: 'Ищи доказуемые языковые ошибки в русском техническом тексте.'}
  verifier: {text: 'Отклоняй гипотезы, которые недостаточно подтверждены контекстом.'}
```

Обязательны `schema_version: 1`, непустой словарь `profiles` и существующий
`default_profile`. Имена профилей: 1–64 символа ASCII, буквы/цифры/`_`/`.`/`-`,
первый символ — буква или цифра. Неизвестные ключи, неверные типы, дубли ключей,
неизвестные стратегии и несовместимые model/effort отклоняются до LLM.
Равнозначная машинная валидация — `project_config.py` и общие типизированные
валидаторы `config.py`; выполняется установленной командой `config validate`.

Разрешённые разделы верхнего уровня: `schema_version`, `default_profile`,
`profiles`, `path_rules`, `prompts`, `scan`, `extract`, необязательный UUID `project_id`.
`scan` и `extract` используют существующие поля инвентаризации и извлечения:
`extensions`, `exclude_dirs`, `exclude_patterns`, `respect_gitignore`,
`follow_symlinks`, `max_file_size`; `header_language`, `message_calls`, `selectors`.
Профиль может точечно переопределить эти два раздела. Термины и языковые настройки
разных профилей не наследуются друг от друга.

| Поля профиля | Потребитель |
| --- | --- |
| `engines`, `categories`, `terms` | Применимость движков, фильтры и терминология |
| `analysis.mode` | `normal`, `adaptive`, `deep` |
| `analysis.strategies`, `analysis.verify` | Шесть существующих стратегий и критический verifier |
| `analysis.max_passes`, `max_requests`, `max_text_chars`, `max_context_chars`, `timeout_seconds`, `concurrency`, `retries` | Существующее бюджетирование проходов |
| `llm.provider`, `llm.model` | `llama_cpp`, `ollama` либо `chatgpt`; модель выбранного провайдера |
| `llm.reasoning_effort` | Только ChatGPT; проверяется существующая матрица model/effort |
| `llm.timeout_seconds`, `batch_chars`, `batch_items`, `max_output_tokens`, `context_tokens`, `seed`, `thinking` | Существующие настройки LLM и упаковки запросов |
| `languagetool.language`, `level`, `disabled_rules`, `timeout_seconds`; `vale.timeout_seconds` | Существующие настройки LanguageTool/Vale |
| `prompts` | Содержательные языковые инструкции эффективного профиля |

Для ChatGPT допустимы только `gpt-6-luna` и `gpt-6.1-sol`; доступность проверяется
по каталогу аккаунта, без подмены. У Luna допустимы `none/low/medium/high/xhigh/max`,
у Sol — `low/medium/high/xhigh/max`. Для локальных провайдеров `reasoning_effort`
недопустим. Их поле `thinking` сохраняет прежнюю транспортную семантику.
Отсутствующая локальная модель сохраняет штатное поведение: llama-server может
выбрать единственную загруженную модель, Ollama использует штатное значение.
Заданная недоступная модель даёт явный отказ.

Числовые границы совпадают с `validate_check_value`: например, `max_passes` 1–8,
`concurrency` 1–16, `retries` 0–3, `max_requests` 1–100000,
`max_text_chars` 1–100000000. Неуказанные бюджеты сохраняют продуктовые значения,
включая ограниченные бюджеты расширенных режимов. Настройки применяются до создания
движка. Единицы одного корня и одинаковой эффективной политики используют один
экземпляр движка и общий бюджет; разные политики/корни — независимые подпрогоны.

## Детерминированные правила

`path_rules` содержит не более 256 правил с `path`, `profile` и необязательным
целочисленным `priority` (по умолчанию 0). Поддерживаются точный относительный путь
и конечный префикс каталога `docs/**`; произвольные glob не поддерживаются.
Разделитель `/`, сравнение регистрозависимое, в том числе в Windows. Абсолютные
пути и сегменты `.`/`..` запрещены. Несуществующие точные пути разрешены: это
политика для будущих файлов, а файл промпта обязан существовать уже сейчас.

Выигрывает максимальный `priority`. Пересекающиеся правила одного приоритета
и повтор одного `path` отклоняются заранее, даже если совпавшего файла пока нет.
Порядок правил и обхода не влияет на результат. Незатронутый путь использует
`default_profile`. Явный `--profile` принудительно выбирает объявленный профиль
для всех выбранных путей, затем применяются разовые параметры CLI.

В одном `check` каждый корень загружается отдельно. Отчёт содержит независимые
записи `engines` с `root_id`, `document_ids`, бюджетами и provenance; имя движка
может повторяться. `documents[].configuration.policy` показывает фактический
профиль, правило, provider/model/effort, режим, источники и fingerprints.
Верхняя `configuration` описывает начальную политику первого входа; для анализа
смешанных корней используйте настройки документов и соответствующих подпрогонов.
Схемы check/review по-прежнему читают прежние версии 1.0/1.1; новое поле политики аддитивно.

## Языковые промпты и неизменяемые гарантии

`prompts.primary`, `prompts.verifier` и `prompts.strategies.<имя>` принимают
`{text: '...'}` либо `{file: '.language-review/prompts/name.md'}`.
Короткая строка означает путь к файлу, а не текст внутри конфигурации. Укажите ровно `text`
или `file`. Все шесть имён стратегий доступны независимо от режима профиля.
Общие overrides наследуются профилем по каждому ключу; профильный override
заменяет только этот ключ. Явный `null` отменяет наследуемый override и возвращает
встроенную инструкцию. Отсутствующий override сохраняет штатную инструкцию.

Файл — UTF-8 Markdown внутри того же корня. Пути разрешаются от корня, выход
через symlink/junction запрещён. Пустой текст, NUL, неверный UTF-8 и превышение
65536 байт дают ошибку. YAML ограничен 262144 байтами, глубиной 16 и 10000 событиями
парсера; якоря, ссылки на них и явные теги запрещены. Нет include, скриптов или сети.

Основной override заменяет содержательные указания; стратегия и verifier получают
соответствующие overrides в настоящих запросах всех трёх транспортов. Продукт
добавляет неизменяемый контракт: схема JSON, дословные цитаты, защищённые вставки,
смысловые инварианты и недоверие к исходникам/памяти. Программные проверки ответов,
масок, координат, исправлений и malformed-ответов действуют независимо от промпта.

`prompts` в диагностике/отчёте содержит `base_version`, SHA-256 основного эффективного
промпта (включая контракт и термины), выбранных стратегий и verifier, а также
относительные источники. Тексты промптов и термины не публикуются. Базовая версия
и `prompt_template_sha256` сохраняются отдельно; override не выдаётся за встроенный
шаблон. Повтор одинаковой политики даёт одинаковые fingerprints.

## Среда, согласия и миграция TOML

Пользовательский `%APPDATA%/language-review/config.toml` и явный `--config TOML`
остаются источниками среды. Явный TOML объединяется поверх пользовательского.
В проектах из них принимаются только адреса локальных движков, `vale.program`,
`vale.config`, `allow_remote_endpoints`, отдельные `llm.chatgpt.allow_cloud` и
`llm.chatgpt.allow_memory`, OAuth и настройки сервиса памяти. Эти поля запрещены
в проектном YAML: репозиторий не получает право подключаться к произвольному
адресу или передавать текст самим выбором `provider: chatgpt`.

Для миграции перенесите `[scan]`/`[extract]` в одноимённые разделы YAML,
`[check]` — в профиль; модель — в `llm.model`, уровень рассуждения ChatGPT — в
`llm.reasoning_effort`. Старые `project_markers` замените явным `default_profile`,
`match_paths` — правилами `path_rules`. Прежние профили, модели, стратегии и термины
из TOML больше не влияют на `scan`/`extract`/`check`. `config show --environment`
позволяет отдельно диагностировать прежнюю конфигурацию TOML. Новый `config show [ПУТЬ]`
показывает проект, эффективный профиль и параметры `scan`, `extract`, `check`
с происхождением каждого значения; без пути используется `.`.

CLI `--profile`, `--model`, `--reasoning-effort`, `--analysis-mode`, `--strategy`
и существующие параметры имеют приоритет над YAML, но не отменяют его обязательность
и валидацию. Облачное согласие для исходников не разрешает передачу памяти;
фоновый обработчик консолидации не получает полномочий из YAML.

Область памяти автоматически связывается с нормализованным абсолютным корнем
и необязательным UUID `project_id` через UUIDv5. Разные клоны и worktree изолированы;
перемещение корня меняет область. Это идентичность, не авторизация. Секреты БД
и включение памяти остаются пользовательскими. Существующий явный
`--memory-project` — операторское переопределение области для одного корня;
для нескольких корней используйте автоматическую привязку. Повторная привязка
одной области к нескольким входным корням отвергается прежним контрактом памяти.

Оценщик `language-review-eval run --config .language-review.yaml` переносит выбранную
политику и ограниченные файлы промптов во временные репозитории, не передавая метки.
Без YAML он явно создаёт безопасные локальные шаблоны для материализованного корпуса;
TOML в `--config` сохраняет роль среды. Capture сохраняет политики документов и hashes
в manifest и исходном review. Это подтверждает воспроизводимость конфигурации,
а не качество живой модели или независимость human gold.
