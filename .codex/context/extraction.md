# Контракт структурного извлечения

`extract` повторно использует выбор файлов, профили, ограничения размера, `.gitignore` и политику ссылок из `scan_paths`. Он читает каждый выбранный файл после обхода и сверяет размер и SHA-256, чтобы не выдавать диапазоны для изменившегося исходника. Исходники не изменяются. Публичная схема `scan` не содержит внутренний хеш.

Ошибка сканера сохраняет общий `reason=scan_error` и исходную причину в `diagnostics`; несовпадение текста фрагмента с диапазоном источника даёт `error` с `reason=fragment_source_mismatch`.

`coordinates.py` строит карту исходных байтов и текста Python. Смещения байтов отсчитываются от начала оригинального файла, включая BOM; строки и столбцы считаются по физическим `LF`, `CRLF` и `CR`; обычный столбец считает Unicode code points, отдельный столбец — UTF-16 code units. Парсеры получают UTF-8 представление; сопоставление позиций выполняется через карту исходных байтов и кодировки.

Каждый фрагмент должен быть точной непрерывной цитатой источника. `extract_report.py` повторно проверяет это равенство перед сериализацией. Защищённые поддиапазоны сохраняют переменные, форматные поля, escape-последовательности, ссылки, inline code, сущности, пути и другие машинные значения внутри фрагментов. ID документа зависит от root ID, относительного пути и SHA-256; ID фрагмента зависит от документа, контекста, диапазона и текста.

`extract_code.py` извлекает документационные и обычные комментарии, PowerShell help-текст и строки известных или настроенных сообщений для Rust, C#, C, C++ и PowerShell. C#-теги документации `<c>` и `<code>` не становятся прозой. Неоднозначный `.h` автоматически даёт частичный статус; `header_language` позволяет явно выбрать `c` или `cpp`. Строка внутри повреждённого вызова пропускается. Ошибка грамматики делает документ частичным и сохраняет только безопасно распознанные фрагменты вне повреждённых узлов.

`extract_docs.py` поддерживает Markdown, GFM-таблицы, plain text, reStructuredText и AsciiDoc. Для Markdown диапазоны сопоставляются с исходными строками и ячейками; если отображение нельзя доказать точно, документ помечается частичным. Разметка и кодовые блоки не становятся текстом сообщения; адреса ссылок и inline code остаются защищёнными диапазонами.

`extract_structured.py` требует явно заданных селекторов для JSON, YAML, TOML и XML. Поддерживаются свойства `.name`, quoted-ключи `['name']`/`["name"]`, индексы массивов `[0]` и wildcard `*`; XML-селекторы используют имена элементов и атрибуты `@name`. Для выбранного XML-элемента CDATA и ссылки на сущности пока пропускаются с `unsupported_xml_content_node` и частичным статусом. YAML анализируется синтаксическим деревом без выполнения тегов или раскрытия alias. Ветви с tag/alias, ошибками грамматики и неподдерживаемыми ключами пропускаются с диагностикой и частичным статусом.

Flow mappings YAML поддерживаются наравне с block mappings. Дублирующиеся ключи JSON/YAML не выбираются: все значения этого ключа в соответствующем объекте/отображении пропускаются, документ получает диагностику и статус `partial`. TOML-массивы таблиц (`[[table]]`) пока пропускаются с `unsupported_toml_table_array`; селекторы массива применяются к обычным значениям-массивам.

Отчёт имеет независимые идентификатор `language-review.extract` и версию `1.0`; JSON Schema и проверенный реальный пример находятся в `docs/extract-report.schema.json` и `docs/extract-report.example.json`. Статусы документа: `extracted`, `skipped`, `unsupported`, `partial`, `error`. Парсер не выбирает языковые ошибки и не исправляет текст.
