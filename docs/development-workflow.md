# Процесс разработки и ревью

Этот документ поясняет рабочий процесс, а не повторяет `AGENTS.md` или реализации скиллов.

## Публикация

Одна задача оформляется отдельной веткой от актуального `main` и PR. Опубликованный SHA, актуальность diff и соответствие исходным требованиям проверяются перед передачей PR. Merge производится только по отдельному запросу. Не включай автоматический merge в Renovate или CodeRabbit.

## Ревью

Независимое code review проверяет требования, соседний код и тесты; CodeRabbit — отдельный, **только явно запрашиваемый** цикл. Найденные провайдером замечания не принимаются автоматически: сначала исследуются source, callsites, симптомы и контракт. Обычно пользователь проводит две волны CodeRabbit по пять итераций с независимым ревью между ними; конкретный запрос имеет приоритет, а стандартный запуск скилла без указанного числа итераций использует три. Deep/normal режим выбирается по прямому указанию, не через эвристику.

## CI и безопасность

PR CI проверяет locked environment, Ruff, mypy и агентские валидаторы на Ubuntu. Полный pytest и packaging smoke выполняются на Windows, где находится поддерживаемый runtime; Linux pytest не является обязательным контрактом текущего Windows-first продукта. Полное исследование security выполняет CodeQL для Python/GitHub Actions, только при поддержке GitHub Code Security. Если работа ещё в приватном репозитории и CodeQL недоступен, отсутствие security status нельзя выдавать за PASS.

Обрабатываемые файлы, результаты экспериментов, credentials, локальные настройки и текстовые отчёты должны оставаться за пределами Git или под `.gitignore`. Для выхода проекта в public проверь историю, а не только текущий checkout. Фактическая доступность внешнего CodeRabbit и Renovate зависит от подключения их GitHub Apps.
