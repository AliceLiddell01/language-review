# Конфигурация и диагностика

Источники истины: `config.py`, `doctor.py`, `tests/test_config.py`, `tests/test_doctor.py`.

- Пользовательская конфигурация находится вне репозитория; явно переданный `--config` перекрывает её, CLI аргументы имеют высший приоритет.
- Профили отбираются по реальным маркерам проекта, приоритету и `match_paths`; не кодируй особенности конкретного внешнего проекта в общую реализацию.
- `config show` обязан показывать происхождение эффективных значений без утечки полей, похожих на секреты, и токенов в параметрах URL; новые способы вывода тоже требуют маскирования.
- Имя в `message_calls` состоит из сегментов, разделённых `.`, `::` или C++ `->`; дефис допустим внутри сегмента (команды PowerShell), `!` — только в конце (макросы Rust). Настроенное имя сравнивается с полным именем вызова без учёта регистра и пробелов.
- Значения `message_calls` профиля добавляются из нескольких конфигурационных файлов; источник эффективного списка включает базовый `message_calls` и каждый файл, внесший профильные вызовы.
- `doctor` диагностирует среду, объявленные программы и настроенные локальные HTTP-сервисы. Отсутствие необязательного сервиса не блокирует `scan`.
- Параметры `extract` и профилей хранятся в `config.py`; подмножество селекторов структурированных форматов и их границы описаны в [extraction.md](extraction.md).
- Конфигурация и диагностика не изменяют пользовательские файлы. При расширении схемы добавляй тесты значений по умолчанию, приоритета, неверных данных, обработки ошибок и маскирования.
