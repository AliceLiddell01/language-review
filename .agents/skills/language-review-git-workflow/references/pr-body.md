# Структура PR и проверяемые утверждения

Ручной PR содержит непустые разделы уровня `##` в этом порядке:

1. `Цель` — какая проблема решается, без выдуманных требований.
2. `Область изменений` — файлы, boundaries, чего PR не меняет.
3. `Реализация` — существенные изменения и технический эффект.
4. `Проверки` — реальные команды, статус PASS/FAIL/PARTIAL/NOT_RUN, окружение.
5. `CI` — ссылка либо `NOT_RUN`, ограничения (например, GitHub-hosted Windows runner).
6. `Готовность` — Draft/Ready, блокеры, что остаётся до merge.
7. `Ограничения` — недоказанные свойства, внешние зависимости, риски.

Проверку структуры выполняет `.github/scripts/check_pr_body.py`. Не прячь отсутствующие доказательства за словами «прошло» или «готово». Bot PR от Renovate/Dependabot обрабатываются по исключению валидатора. Если был явно проведён CodeRabbit cycle, добавь раздел `## CodeRabbit review и disposition` и таблицу `| Итерация / reviewed HEAD | Уровень | Путь | Влияние | Решение | Исправление |`. Каждая итерация учитывает **reviewed HEAD**, а не commit исправления. Длинную историю/логи не переписывай в PR: приводи агрегированную таблицу с проверяемой ссылкой на provider evidence.
