# Language Review 0.1.0-beta.1

Target SHA: @TARGET_SHA@
Предыдущий стабильный выпуск: none.

## Изменения

Первый кандидат Windows pre-release объединяет локальные CLI `scan`, `extract`,
`check`, проверяемые review-отчёты и проектную языковую политику с профилями.
Поддержаны LanguageTool, Vale и LLM, многоступенчатый анализ, добровольный ChatGPT
OAuth, отдельный оценщик и предметная память PostgreSQL/pgvector с очередью worker,
явными решениями и структурным/гибридным recall.

Поставка включает wheel/sdist, закреплённые зависимости в Windows wheelhouse,
PowerShell bootstrap, setup, диагностику установки, обновление/откат и глобальные
пользовательские skills Codex и Claude Code. Notes кандидата получают полный
target SHA при подготовке, без циклической зависимости содержимого commit от его SHA.

## Совместимость

Выбрана версия 0.1.0-beta.1: это первый публичный кандидат начальной разработки,
а не обещание стабильного API. SemVer соответствует package version `0.1.0b1`.
Требуются Windows x64, PowerShell 7 и Python 3.15 в изолированном runtime установки.
Проектный YAML сохраняет `schema_version: 1`; версии check/review не меняются
вместе с номером продукта. Исследуемые исходники CLI не исправляет автоматически.

## Миграции и откат

Предыдущего опубликованного stable нет: проверка обновления с него и отката к нему
не выполняется с причиной `no_predecessor`. Проект настраивается отдельным YAML;
установка не создаёт его и не выдаёт согласий на облачную передачу данных.
Изменённые пользовательские skills не перезаписываются.

Worker обновляется отдельно от CLI. Миграции БД не откатываются вместе с runtime;
перед обновлением существующей памяти нужен backup, а совместимость прежнего worker
после миграции проверяет установщик службы. При несовместимости требуется
восстановление backup. Удаление CLI сохраняет пользовательские настройки, OAuth,
службу памяти и её данные. Для первого выпуска возврат к прежней опубликованной
версии недоступен.

## Ограничения

Bootstrap проверяет integrity через официальный GitHub API/TLS и SHA-256;
это не независимая криптографическая подпись. Docker, языковые серверы, Vale
и модели не устанавливаются автоматически. Облачные тексты и recall требуют
отдельных согласий. OAuth-сессия их не заменяет.

Windows acceptance кандидата не доказывает публичную загрузку Release, живой
вызов skill моделью, работоспособность пользовательского OAuth либо worker/БД.
Эти проверки требуют отдельных эксплуатационных свидетельств. Память не обещает
измеренного улучшения языкового качества. SARIF, Git diff и автоматическое
применение исправлений не реализованы. Успешная beta-приёмка не означает
готовность stable.
