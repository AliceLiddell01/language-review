# CodeRabbit — checklist исполнителя

- Перед запуском проверь Windows PowerShell, `coderabbit --version`, `coderabbit --help`, `git status`, `git rev-parse HEAD`, фактический PR и SHA удалённой ветки. Если есть только удалённый API и локальный CLI недоступен, не заявляй, что проверка CodeRabbit выполнена.
- Определи base из актуального PR, не из зашитой в конфигурацию ветки. Проверь полный актуальный diff, вызывающий и вызываемый код, затронутые модули, тесты и контракты; глубину проверки определяй фактическим риском изменения.
- Не передавай публичным сервисам приватные исходники пользовательских репозиториев, локальные результаты или токены. Запрошенная CLI-проверка касается зафиксированных исходников Language Review.
- Разделяй вывод сервиса, разбор замечаний и исправление. Обоснование `false positive` должно ссылаться на конкретный код и требования.
- Для реального замечания CodeRabbit применяй критерии `language-review-code-review`; при отсутствии дефекта не вноси косметические изменения.
- Новую итерацию начинай только после завершения предыдущей, включая проверки и публикацию на сервере.
- В итоговом описании PR используй таблицу `| Итерация / reviewed HEAD | Уровень | Путь | Влияние | Решение | Исправление |`; указывай подтверждённое влияние и решение по каждому существенному замечанию, не скрывай блокеры.
