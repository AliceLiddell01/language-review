# Цикл ревью CodeRabbit

## Активация

Только явная просьба «запусти/продолжи CodeRabbit», число итераций, режим `deep` или `focus`. Само упоминание CodeRabbit, редактирование `.coderabbit.yaml` или обычное ревью кода **не** разрешают запуск. По умолчанию выполняются три завершённые итерации, если пользователь не указал другое положительное число. Две волны по пять — отдельный порядок работы по просьбе пользователя, а не фоновая задача.

## Контракт цикла

1. Прочитай `AGENTS.md`, применимый контекст, [review-workflow.md](references/review-workflow.md) и `language-review-git-workflow`. Проверь текущую рабочую копию, опубликованный HEAD, PR и установленный CLI; найди **реальные** флаги через `--help`, не выдумывай.
2. Работай с опубликованным коммитом HEAD; не выдавай непубликованные рабочие изменения за проверенный PR. Не запускай несколько проверок одновременно и не сокращай объём молча.
3. Запускай запрошенный режим `normal`/`deep`/`focus` (режим `deep` — только по явному запросу). Проверяй, что вывод сервиса полный и охватывает нужный код; код возврата 0 сам по себе не доказывает завершение ревью.
4. Для каждого замечания укажи `confirmed`, `partially confirmed`, `stale/repeated` или `false positive` по проверенному HEAD, коду, тестам, контракту и техническому эффекту. Не применяй созданный patch без проверки.
5. Исправляй только подтверждённые причины дефектов, не ослабляя тесты; выполняй нужные проверки в Python/Windows. Затем создай отдельный commit, отправь его через Git workflow, проверь точный SHA на сервере, обнови описание PR и перечитай опубликованный PR и рабочее дерево.
6. Следующую итерацию начинай только после успешного завершения предыдущей. Исправленный commit **не** является reviewed SHA предыдущей итерации.

## Чистый результат, ошибки и платные запросы

Пустой commit `git commit --allow-empty` допустим только после полностью завершённого ревью без замечаний и при доказанном чистом результате в рамках согласованной серии итераций. Ограничение частоты, неполный вывод сервиса, ошибка аутентификации, запрос оплаты, неудачная проверка или отправка commit означают `NOT_COMPLETED`, а не чистый результат. Соблюдай интервал повторной попытки сервиса, не проверяй статус слишком часто. Не включай платный режим самостоятельно.

Запрещены: автоматическое изменение `.coderabbit.yaml` по замечанию ревью, принудительная отправка ветки, merge без разрешения, подмена CLI API и выдуманные результаты. В отчёте укажи число запрошенных и завершённых итераций, проверенный SHA, количество замечаний по статусам, результат публикации и оставшиеся блокеры.
