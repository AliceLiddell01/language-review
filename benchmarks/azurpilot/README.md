# Замер `check` на AzurPilotRu

Одноразовая воспроизводимая проверка достоверности `check` на настоящих текстах внешнего репозитория AzurPilotRu. Это не benchmark-фреймворк и не заявление о качестве на других репозиториях.

## Что зафиксировано

| Файл | Содержимое |
| --- | --- |
| `manifest.json` | HEAD AzurPilotRu (`565c878`), относительные пути и SHA-256 (по содержимому с LF) 19 файлов `docs/` и 12 файлов образца |
| `labels.json` | Предварительная **агентская** разметка (не подтверждена человеком); составлена по исходным текстам **до** просмотра результатов `check` |
| `run_benchmark.py` | Запуск, проверка корпуса по манифесту, подсчёт охвата и сопоставление с разметкой; `--rescore` пересчитывает только оценку по сохранённому отчёту |
| `results-after.json`, `results-before.json` | Агрегаты: код `701ff28` (после) и `59f267a` (до, PR #7) на одном корпусе и конфигурации |
| `make_charts.py`, `charts/` | Диаграммы PR, построенные из `results-*.json` (SVG; PNG получены из SVG браузером) |

Корпус не меняется и не копируется в репозиторий: нужен отдельный экспорт `git archive 565c878ee97c852ebf728e3d989ccc1c0fab1229` из AzurPilotRu (рабочая копия на момент замера содержала чужие незафиксированные правки, поэтому использовался экспорт коммита). Сырые отчёты `check` содержат цитаты исходников и не публикуются.

## Воспроизведение

```powershell
git -C <AzurPilotRu> archive 565c878ee97c852ebf728e3d989ccc1c0fab1229 -o corpus.tar   # распаковать в пустой каталог
uv run --locked python benchmarks/azurpilot/run_benchmark.py --corpus <каталог корпуса> `
  --languagetool http://127.0.0.1:8081 --llama-cpp http://127.0.0.1:8082 `
  --label after --output results-after.json
```

Для «до» передай `--python` интерпретатор окружения рабочей копии коммита `59f267a`.

Условия замера: LanguageTool 6.6 (`ru-RU`, уровень по умолчанию), Vale 3.24.0 со встроенными правилами, llama.cpp `b10299-e40bf8864`, модель Gemma 4 E4B (`gemma-4-e4b`, Q4_K_M по `/props`, 7,5 млрд параметров; веса взяты из локального хранилища Ollama), `-c 8192 -ngl 99 --jinja`, `thinking = false`, `temperature = 0`, `seed = 0`, `batch_chars = 1500`, `batch_items = 8`. GPU NVIDIA RTX 3060 Ti 8 ГиБ. Серверы были прогреты (тёплый запуск), «до» и «после» шли последовательно без другой нагрузки. Версии конфигурации одинаковы; различаются только код `check` и `PROMPT_VERSION` (`ru-technical-review/1` и `/2`).

## Образцы

- **Полный `docs/`** (19 файлов, 2994 фрагмента, 1930 единиц): только LanguageTool и Vale. Размеры и охват — в `results-*.json`.
- **Образец** (12 файлов, 379 единиц): документация (4 файла), C# и C++ с русскими комментариями и сообщениями; все три движка. Разметкой покрыты только перечисленные в `labels.json` диапазоны строк (`reviewed`): все строки семи файлов и только строки сообщений в пяти остальных. Находки вне диапазонов в оценку не входят.

## Разметка и метрики

- `defect` — однозначная ошибка; `debatable` — спорное место (регистр, смесь языков в терминах, необязательная запятая): находка по нему не TP и не FP; всё остальное в диапазонах считается корректным и находка по нему — FP. Языковая политика самого AzurPilotRu (`.codex/context/language.md`) допускает латиницу для идентификаторов и устоявшихся терминов.
- Находка считается попаданием в дефект, только если совпали место и категория (по сути). Попадания по месту с другим диагнозом считаются FP и отдельно считаются в `location_hits_other_essence`.
- В размеченном объёме найден **один** дефект. Этого недостаточно для оценки полноты, поэтому `recall` и `F1` равны `N/A` (`null`); публикуются TP/FP/FN, число находок и характер ложных срабатываний. Объём не расширялся искусственными ошибками.
- Ограничения: единственный размечающий — агент; разметка могла пропустить дефекты; FP по LLM разобраны выборочно (каждое четвёртое замечание прочитано вручную, все — ложные или спорные по политике проекта).
- Не измерено: полнота на любых репозиториях, качество Ollama и других моделей и квантований, холодный запуск, поведение на английской прозе в объёме, достаточном для оценки (в корпусе почти нет самостоятельных английских абзацев: на весь экспорт корпуса (11 040 единиц) под критерий проверки LLM подходят 16 единиц, это заголовки и подписи).
