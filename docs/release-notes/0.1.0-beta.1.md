# Language Review 0.1.0-beta.1

Target SHA: @TARGET_SHA@
Предыдущий стабильный выпуск: none.

## Изменения

Первый кандидат начальной разработки объединяет локальные CLI `scan`, `extract`,
`check`, проверяемые review-отчёты и проектную языковую политику с профилями.
Поддержаны LanguageTool, Vale и LLM, многоступенчатый анализ, добровольный ChatGPT
OAuth, отдельный оценщик и предметная память PostgreSQL/pgvector с очередью worker,
явными решениями и структурным/гибридным recall.

Комплект Windows x64 включает самостоятельный `install.exe`, wheel и sdist,
hash-locked requirements для extras и `wheelhouse.zip` с проверенными зависимостями.
Установщик настраивает изолированный runtime CLI, поддерживает диагностику и явные
обновление/откат. При обычной установке он регистрирует каталог launcher в
пользовательском `PATH` (`--no-path` отключает это); skills Codex и/или Claude Code
устанавливаются по явному выбору. Отдельная служба предметной памяти работает в
собственном Python runtime и устанавливается отдельно. Маркер `@TARGET_SHA@` в notes
заменяется полным target SHA при подготовке кандидата, без циклической зависимости
содержимого commit от его SHA.

## Совместимость

Выбрана версия `0.1.0-beta.1` — первый кандидат начальной разработки с нестабильным
API; SemVer отображается как package version `0.1.0b1` по PEP 440. Требуются Windows
x64 и доступ к GitHub Releases. Установка не требует checkout, заранее установленного
Python, `uv`, PowerShell или прав администратора. Если `uv` отсутствует, `install.exe`
получает проверенную версию `uv` 0.13.1; имеющийся `uv` должен быть не ниже 0.13.1.
Через `uv` создаётся отдельный venv с Python 3.15; при необходимости интерпретатор
загружается по модели managed Python uv. Системный Python не изменяется. CLI устанавливается
из hash-locked requirements только бинарными wheel из проверенного wheelhouse.
ARM64 пока не проверен. Для установки этого pre-release передайте полный tag:
`install.exe --tag v0.1.0-beta.1`.

Проектный YAML сохраняет `schema_version: 1`; версии check/review не меняются вместе
с номером продукта. Исследуемые исходники CLI не исправляет автоматически.

## Миграции и откат

Предыдущего опубликованного stable нет (`previous_stable=none`), поэтому обновление
и откат относительно прежнего stable для этого кандидата не выполняются с причиной
`no_predecessor`. Проект настраивается отдельным YAML; установка не создаёт его и не выдаёт согласий на
облачную передачу данных. Изменённые пользовательские skills не перезаписываются.

Если прежняя локальная установка использует `.cmd` или PowerShell launcher, новый
bootstrap откажется менять её. Сначала проверьте `install.exe` в отдельном пустом
каталоге с `--root`, `--no-path` и `--non-interactive`; затем удалите прежнюю
установку её CLI-командой `language-review installation uninstall`, дождитесь результата
в `uninstall-result.json` и запустите `install.exe` без `--root`.
Удаление CLI сохраняет пользовательские настройки,
OAuth, службу памяти, PostgreSQL volume и данные. Вручную удалять старую установку
не следует. Если прежний CLI не завершает удаление, сохраните старую установку
для восстановления и используйте отдельный пустой root.

Обновление CLI не обновляет отдельный worker. Его установка или обновление выполняется
явно через `language-review setup --memory-service`: служба устанавливается из wheel
проверенного release directory в собственный Python runtime, checkout не требуется.
При ошибке готовности установщик worker восстанавливает прежние файлы runtime и задачу,
но не отменяет уже применённые миграции БД. Перед обновлением worker сделайте backup;
после отката проверьте совместимость прежнего worker с текущей схемой. Если проверка
не проходит, восстановите backup.

## Ограничения

Bootstrap проверяет официальный GitHub API/TLS, идентичность релиза, размеры assets
и SHA-256; это проверка целостности в доверенной границе GitHub, а не независимая
криптографическая подпись. Она не защищает от компрометации аккаунта издателя и не
подтверждает Sigstore attestation. Языковые серверы, Vale, Docker, Ollama и модели
не устанавливаются автоматически. Облачная отправка текстов и облачный recall требуют
отдельных согласий; OAuth-сессия их не заменяет.

Windows acceptance кандидата не доказывает публичную загрузку Release, живой вызов
skill моделью, работоспособность пользовательского OAuth либо отдельную приёмку
worker/БД. Эти проверки требуют самостоятельных эксплуатационных свидетельств.
Память не обещает измеренного улучшения языкового качества. SARIF, Git diff и
автоматическое применение исправлений не реализованы. Успешная beta-приёмка не
означает готовность stable.
