# Проверка через установленный Language Review

Вызывай `language-review` из PATH. Сначала проверь `Get-Command language-review`,
`language-review --version` и `language-review installation status`.
Версия CLI должна совпасть с product-version этого skill; dev checkout не является
глобальной установкой. При отсутствии CLI предложи официальную установку, при drift —
`language-review setup` после исправления установки. Не устанавливай ничего молча.
Готовность окружения показывает `language-review doctor --format json`;
отсутствие необязательного сервиса не означает готовность соответствующего анализа.

Для анализа определи настоящий корень Git/worktree каждого входа. Прочитай его
`.language-review.yaml`, выполни `language-review config validate <корень>` и
при необходимости `language-review config show <корень> --format json`.
Без YAML объясни отдельную команду `language-review init <корень>`, не выполняй её
без явного запроса. Невалидный YAML, несовместимый schema_version, неизвестный движок
или неоднозначные корни требуют исправления выбора пользователя до анализа.
Каждый корень имеет собственную политику; не наследуй YAML соседнего репозитория.

Запусти `language-review check <цель> --view review --format json --output <отчёт>`.
Сохраняй отчёт вне исследуемых исходников. Не задавай модель, effort, стратегию
или prompts вместо проекта. Не подменяй поиск собственным LLM-анализом, не запускай
другой движок при отказе выбранного. Не выдавай OAuth, YAML или согласие на установку
за разрешение cloud/cloud-memory; используй только существующие согласия продукта.

Сверь exit code и JSON: 0 — clean при полной coverage, 1 — findings,
2 — ошибка ввода/конфигурации, 3 — ошибка записи/окружения, 4 — partial,
5 — unavailable, 6 — ошибка памяти. Неполный анализ не является clean.
Покажи evidence и ограничения coverage, отличай предложения от доказанных ошибок.
Для готового отчёта используй `language-review show-review <отчёт>` и
`language-review verify-review <отчёт> --root ID=<корень> --format json`.
Перед обсуждением применимости проверь все root IDs: сопоставляй корни входов отчёта,
для файлового входа указывай сам файл, для каталога — каталог; это может отличаться
от корня Git, где находится YAML. Source hash mismatch запрещает
считать цитату актуальной и применять правку по старым координатам. Новый анализ
требует тех же согласий, что обычный check.

В режиме анализа исходники остаются неизменными. Только по разрешённой пользователем
задаче исправления предложи минимальную правку, проверь актуальность evidence,
внеси её и повтори check. Факт изменённого diff, clean повтор или молчание пользователя
не являются решением accepted. При явно сформулированном собственном решении агента
можно вызвать `language-review decide-review <decision.json>` по установленной
`language-review.decision` 1.0 схеме из пакета: укажи actor вида `agent:<имя/версия>`,
reason с обоснованием и реальным evidence; не используй human provenance
и не объявляй это независимым gold. Используй реальные project/run/item идентификаторы
и expected_revision, перед отправкой выполни verify-review исходного отчёта. Если память отключена или полномочий нет,
сообщи это; не включай её. Автоматический ingest уже принадлежит check, дополнительное
сохранение каждой находки не нужно. Допустимые решения: accepted/rejected/disputed.

Skill не меняет глобальные AGENTS.md/CLAUDE.md, проектные политики или согласия.
