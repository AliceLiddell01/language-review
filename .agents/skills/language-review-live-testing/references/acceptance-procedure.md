# Проверка реального Language Review

1. Запусти `uv sync --locked`, статические проверки и модульные тесты согласно `.codex/context/verification.md` — документу с каноническим перечнем проверок Windows.
2. Запусти `uv run --locked python scripts/verify-package.py` в Windows; скрипт должен собрать wheel и sdist, установить их отдельно и вызвать *установленный* CLI, а не импортировать исходники через `PYTHONPATH`.
3. Подготовь синтетические входы `.rs`, `.cs`, `.cpp`, `.md` и случаи с BOM, CRLF, Unicode, смешанной кодировкой, двоичным содержимым, превышением размера, игнорируемыми и недоступными файлами, символическими ссылками и циклами (если это позволяет ОС).
4. Для `scan` сравни JSON и статус с текущим публичным контрактом; проверь, что исходные файлы не изменились и ошибки не вызвали побочных эффектов.
5. Для `extract` и `check` сравни JSON с действующими схемами `language-review.extract` и `language-review.check` (для `check --view review` — `language-review.review`), а коды завершения — с документированными в `README.md` и `.codex/context/check.md`. Включи отрицательные случаи: неверный путь или конфигурацию, неподдерживаемые и частично извлечённые файлы. После каждой команды сверь байты исходников.
6. Для `check` проверь недоступный выбранный движок: отчёт честно показывает `unavailable` с соответствующим кодом, а движок или LLM-провайдер не подменяется другим. Обращения идут только к выбранным движкам по заданным адресам; нелокальный адрес используется только при явном `check.allow_remote_endpoints = true` и только указанный.
7. Если задача затрагивает review, проверь, что `show-review` и `verify-review` читают сохранённый отчёт без повторного анализа и без изменения исходников, а `verify-review` обнаруживает изменённую копию входа.
8. Для `config show` проверь приоритет параметров и маскирование токенов; для `doctor` — доступные и недоступные явно заданные локальные сервисы. Не обращайся к внешней сети без необходимости.
9. Проверь Ctrl-C и коды завершения только в изолированной среде, без риска прервать пользовательскую сессию.
10. Удали созданные временные данные, не удаляя чужие файлы. Верни таблицу результатов и укажи пропущенные платформы.
