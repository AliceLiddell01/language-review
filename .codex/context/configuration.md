# Конфигурация и диагностика

Источники истины: `config.py`, `doctor.py`, `tests/test_config.py`, `tests/test_doctor.py`.

- Пользовательская конфигурация находится вне репозитория; явно переданный `--config` перекрывает её, CLI аргументы имеют высший приоритет.
- Профили отбираются по реальным project markers, priority и `match_paths`; не кодируй особенности конкретного внешнего проекта в общую реализацию.
- `config show` обязан показывать происхождение эффективных значений без утечки secret-like полей/URL query-токенов; новые способы вывода тоже требуют redaction.
- `doctor` диагностирует окружение, объявленные программы и настроенные локальные HTTP endpoints. Отсутствие необязательного сервиса не блокирует `scan`.
- Конфигурация и диагностика не изменяют пользовательские файлы. При расширении схемы добавляй тесты default, precedence, invalid input, error path и masking.
