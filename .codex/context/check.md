# Контракт языковой проверки `check`

Источники истины: `check.py` (конвейер, проверка предложений, согласование, статусы), `masking.py` (виды для движков и обратное отображение), `engine_languagetool.py`, `engine_vale.py`, `engine_llm.py`, `engine_http.py`, `check_report.py`, `vale_styles/LanguageReview/*.yml`, `docs/check-report.schema.json`, `tests/test_check.py`, `tests/test_masking.py`, `tests/test_check_live.py`.

- Вход — только фрагменты `extract_paths`; `check` не читает файлы сам и не обходит селекторы. Документы `partial`/`unsupported` проверяются по безопасно извлечённым фрагментам, но статус остаётся `partial`.
- Единица проверки — фрагмент или соседние строки одного абзаца/комментария (одинаковые `kind` и `context`, следующая строка, для комментариев — тот же столбец). Единицы без кириллицы пропускаются с `no_russian_text` и не считаются неполнотой.
- Вид для движка строится `build_view`: защищённые диапазоны и технические токены → заглушка (`X` для LanguageTool/Vale, `⟦n⟧` для LLM), escape/сущности/разметка → буквальное значение или пусто, CR → маска, соединение строк → маска `\n`. Позиция внутри маски не отображается; вставка у пустой маски неоднозначна и отклоняется; правка, пересекающая маску, — `rejected`.
- Координаты движков: LanguageTool — UTF-16 (`EngineView.utf16_index`), Vale — строка и столбец code point от 1 с включительным концом и сверкой `Match`, LLM — дословная однозначная цитата `excerpt` внутри отправленного элемента. Координаты исходника вычисляются `coordinates.position_within` по точной цитате фрагмента.
- Ответ LLM проверяется вручную, без доверия грамматике JSON: ровно ключ `findings`, известные `item`, категории и уверенность, границы длины, наличие цитаты, отсутствие тождественной замены и дубликатов. Неверный JSON, обрезанный ответ или нарушение схемы — сбой единиц (`llm_*`), а не чистый результат.
- Промпт и схема общие для `llama_cpp` и `ollama`; провайдер — только транспорт. Изменение `SYSTEM_PROMPT` или схемы требует новой `PROMPT_VERSION`; отчёт хранит версию и `prompt_sha256`.
- Предложение `candidate` — не проверенное исправление: оно прошло проверки отрицаний, технических токенов, экранирования и границ, но не применяется. `suggestions_applied` всегда `false`.
- Согласование объединяет только реально пересекающиеся диапазоны одной единицы и совместимых категорий (`CATEGORY_GROUPS`); источники и их уверенность сохраняются отдельно, общая вероятность не вычисляется.
- Статусы движка: `ok`, `partial`, `error`, `unavailable`; документа: `clean`, `findings`, `partial`, `unavailable`, `error`, `skipped`, `unsupported`; итог: `clean`, `findings`, `partial`, `unavailable`, `error`. Коды `check`: 0, 1 (замечания), 2 (вход/конфиг), 3 (запись отчёта), 4 (неполно), 5 (движок недоступен или ошибка). Коды остальных команд не меняются.
- Выбранный движок или провайдер не заменяется другим; три подряд сбоя транспорта прекращают отправку (`engine_aborted`). HTTP-клиент не использует прокси и перенаправления, ограничивает размер ответа.
- Отчёт не содержит локальных путей: источники настроек обобщаются `public_source`, Vale не публикует текст своих ошибок, из `/props` llama-server берутся только версия сборки и квантование.
- Схема `language-review.check` 1.0 и пример `docs/check-report.example.json` меняются вместе; пример строится фактическим CLI на `prepare_example_inputs` из `tests/test_check_live.py`.
