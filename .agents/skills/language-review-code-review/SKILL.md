# Независимое код-ревью

## Источники и охват

1. Установи исходный request/issue, точные base/head, scope diff и текущее состояние code/test/config; если постановка недоступна, не придумывай её.
2. Изучи diff и окружающий код: calls/callees, serializers, файловые границы, конфигурацию, тесты, CI. Сверь `AGENTS.md` и релевантные `.codex/context/`; не считай комментарий выше работающей реализации.
3. Проверяй корректность, безопасность, data leaks, symlinks/path traversal, Unicode/BOM, multi-root scan, exit codes, backward compatibility, стабильность JSON, детерминизм, ошибочные default settings, хардкод без владельца, dead code и необоснованный scope creep.
4. Тесты должны защищать публичный контракт и реальную программу, а не хрупкую фиксацию текущей реализации. Отмечай привязку fixture к конкретной машине/PR и fake tests, которые просто проверяют собственную подмену.
5. Запускай релевантную верификацию, если доступна. Вспомогательные одноразовые read-only скрипты, fixtures и логи ревью — только во внешнем системном temp, не в исходном репозитории. Не меняй продукт/PR в режиме независимого ревью.

## Findings

Для каждого actionable finding: severity, точный путь/строки на reviewed SHA, фактическое нарушение, условия воспроизведения, технический эффект и минимальное исправление. Учитывай [finding-policy.md](references/finding-policy.md). Не выдавай предположения за ошибки; если данных недостаточно, укажи missing evidence. Проверяй дубликаты и уже исправленные дефекты.

## Результат

Сначала подтверждённые findings по важности, затем соответствие требованиям и тестам, среда/результаты проверок, риски и пределы ревью. При отсутствии findings говори, что не обнаружено доказанных дефектов в просмотренной области, а не что код «идеален». CodeRabbit является отдельным провайдерским процессом.
