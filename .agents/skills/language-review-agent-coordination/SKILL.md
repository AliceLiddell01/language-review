# Координация субагентов

## Когда делегировать

- Соблюдай явный запрет. Если пользователь не просил делегирование, оцени, ускорит ли оно независимую работу или улучшит ревью. Тривиальные неделимые задачи решай без субагентов; лимит в шесть исполнителей — потолок, не квота.
- При явном запросе на субагентов назначай независимые направления. Невозможность делегирования обозначь, не имитируй участие другого агента.
- Основной агент отвечает за постановку задачи, разрешение конфликтов и интеграцию. Передавай точный checkout, Windows/PowerShell execution boundary, применимые `AGENTS.md`, `.codex/context/` и project skills.

## Избежание гонок

- Для каждого изменяемого файла назначай одного писателя. Передача ownership — только после завершения первого. Пересекающиеся правки выполняй последовательно или в изолированных worktrees с контролируемым merge.
- Разделяй задачи по независимым артефактам: scanner, configuration, test coverage, CI/review infrastructure. Не позволяй нескольким субагентам одновременно менять `uv.lock`, `pyproject.toml`, `AGENTS.md`, один PR body или Git index.
- Shared `uv sync`, сборка, тесты с общими временными путями, Git/PR operations — последовательно либо с отдельными outputs и окружениями. Субагентам не делегируй одновременно обновление одной ветки.
- Git/публикацию и PR делает один owner после интеграции всех писателей; при параллельном review все reviewers читают зафиксированный HEAD.

## Интеграция

Прочитай итоговый diff, уточни ownership, выполни полный применимый gate на объединённом состоянии и проверь удалённый HEAD. Отчёт исполнителя без фактического лога не означает PASS; заявлять «независимое ревью» можно только если оно реально было.
