# Координация субагентов

## Когда делегировать

- Соблюдай явный запрет. Если пользователь не просил делегирование, оцени, ускорит ли оно независимую работу или улучшит ревью. Тривиальные неделимые задачи решай без субагентов; лимит в шесть исполнителей — потолок, не квота.
- При явном запросе на субагентов назначай независимые направления. Невозможность делегирования обозначь, не имитируй участие другого агента.
- Основной агент отвечает за постановку задачи, разрешение конфликтов и интеграцию. Передавай точную рабочую копию, ограничения среды Windows/PowerShell, применимые `AGENTS.md`, `.codex/context/` и процедуры проекта.

## Избежание гонок

- Для каждого изменяемого файла назначай одного писателя. Передача ownership — только после завершения первого. Пересекающиеся правки выполняй последовательно или в изолированных worktrees с контролируемым merge.
- Разделяй задачи по независимым артефактам: обход файлов, конфигурация, покрытие тестами, CI и инфраструктура ревью. Не позволяй нескольким субагентам одновременно менять `uv.lock`, `pyproject.toml`, `AGENTS.md`, одно описание PR или индекс Git.
- Общие `uv sync`, сборку и тесты с общими временными путями, а также операции Git/PR выполняй последовательно либо в отдельных средах с разными результатами. Не поручай субагентам одновременно обновлять одну ветку.
- За Git, публикацию и PR отвечает один исполнитель после интеграции всех изменений; при параллельном ревью все участники читают зафиксированный HEAD.

## Интеграция

Прочитай итоговый diff, проверь владельцев изменённых файлов, выполни все применимые проверки в объединённом состоянии и проверь удалённый HEAD. Отчёт исполнителя без фактического журнала не означает PASS; заявлять «независимое ревью» можно только если оно действительно проводилось.
