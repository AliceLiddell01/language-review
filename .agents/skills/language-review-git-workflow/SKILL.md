# Git и PR — владелец жизненного цикла

## Область ответственности и маршрутизация

Эта процедура описывает ветки, индекс, commit, push, PR и проверку итогового состояния на сервере; она не владеет кодом, CI или CLI CodeRabbit. В начале работы с Git/PR прочитай [pr-lifecycle.md](references/pr-lifecycle.md); перед созданием или редактированием PR — [pr-body.md](references/pr-body.md). Цикл CodeRabbit описан отдельно. Не добавляй в поручения искусственный запрет push.

## Предусловия

1. Установи фактическую рабочую копию, `git status --porcelain=v1`, текущую ветку, remotes, base ref и точный HEAD. Не угадывай `origin`, имена основной ветки, Git identity, права или принадлежность локальных изменений текущей задаче.
2. Не включай посторонние незафиксированные файлы в PR. Сверяй объём задачи, `git diff --check` и релевантные проверки из `.codex/context/verification.md`.
3. Одна самостоятельная публикация — одна ветка и один PR. Если ветка существует, продолжай её; для новой задачи создай ветку от актуальной основной ветки. Не перезаписывай чужую ветку или историю.
4. После commit продолжай штатную процедуру: push, сверка точного SHA на сервере, создание или обновление PR, перечитывание PR и подтверждение base/head. Локальный commit сам по себе не означает публикацию.

## Безопасная публикация

- Добавляй в индекс только файлы задачи (не запускай `git add -A` без проверки); изучи staged diff. `uv.lock` обновляй штатной командой `uv lock`, а не вручную.
- Не используй принудительный push, `--force-with-lease`, reset или автоматический merge/rebase опубликованной ветки для обхода проблем. При конфликтах изучи изменения обеих сторон, разреши их без потерь и снова проверь diff.
- Не создавай второй PR для той же задачи. Описание PR должно содержать проверяемые разделы, реальные команды, PASS/FAIL/PARTIAL/NOT_RUN и границы доказательств. Отмечай изменения продукта отдельно от инфраструктуры.
- Слияние, удаление ветки и очистка после слияния требуют отдельного актуального поручения пользователя.

## Завершение

Сообщи ветку, SHA commit, SHA на сервере, URL/номер PR, подтверждения CI или NOT_RUN, изменённые файлы и блокеры. При работе только через GitHub connector проверь созданные tree/commit/ref через API и перечитай diff/PR.
